---

에이전트가 반복해서 수행할 작업의 판단 기준과 절차를 작성한다. 기존 지식만으로 놓치기 쉬운 도메인 규칙, 도구·서비스 동작과 실제 실패 조건을 남긴다.

## 절차

1. 요청한 작업·입력·기대 결과·적용 시점을 정하고 기존 스킬·참고 자료·생성기에서 같은 책임의 정본을 찾는다. 여러 역할은 한 결과에 기여하는 방식을 설명하고 프로젝트 관례는 프로젝트 지침에 둔다.
2. 유지할 계약과 바꿀 동작을 구분한다. 권한·상태 전이·실패 처리·도구가 읽는 필드를 보존하고 생성 스킬은 원본을 고친 뒤 재생성한다.
3. [Agent Skills 규격](https://agentskills.io/specification)의 YAML frontmatter 뒤에 목적 → `## 절차` 번호 목록 → `## 결과` → `## 예시` → 필요할 때 `## 경계` → `## 참고 자료` 순서로 쓴다. 필드 규칙은 아래 표를 따른다.
4. 한국어 `~한다` 문체로 관찰할 조건과 행동을 연결한다. 호출명·코드·명령·상태값·직접 인용은 원문을 보존하고 언어 용례는 해당 언어로 쓴다. 실제 피해나 책임 경계는 경계 목록에 모은다. 의무·권장·허용과 불확실성을 보존한다.
5. 매번 필요한 판단은 본문에, 긴 상황별 설명은 참고 자료에 두고 읽을 조건을 링크 옆에 쓴다. `scripts/`는 실행 도구, `references/`는 세부 자료, `assets/`는 양식·자원으로 쓴다. 일반론·반복·가상 합리화 목록·근거 없는 효능 주장은 제거하고 입력·행동·결과 예시를 넣는다. 이미 확인한 승인은 유지하고 새 결정에 의존하는 작업만 확인한다.
6. 아래 변경별 검사와 사용 가능한 validator·로더를 실행한다. `skills-ref validate ./my-skill`은 frontmatter와 이름 검사다. 로더 발견·설치, 명시적 지침 적용, 자동 호출과 실제 결과 품질은 각각 구분해 기록한다. 문구·경로 정리는 같은 구현을 반복하는 테스트 대신 해당 검사를 쓴다.
7. diff를 승인 범위와 대조하고 실제 검사·남은 불확실성을 보고한다. 여러 단계 조정 작업은 [연속성](../../references/continuity.md)에 원본·근거 위치를 기록한다.

| 필드 | 작성 규칙 |
| --- | --- |
| `name` | 기존 호출명을 유지한다. 새 이름은 소문자 영문·숫자·하이픈 1–64자로 디렉터리와 맞춘다. 앞뒤·연속 하이픈은 제외한다. |
| `description` | 역할·사용 상황을 1–1,024자로 설명하고 필요한 대상·증상·도구를 포함한다. 길이는 값 자체 기준이며 세부 절차는 본문에 둔다. |
| 선택 필드 | `license`, `compatibility`, `metadata`는 필요한 정보만 넣고 플랫폼 전용 필드는 로더 지원을 확인한다. |

| 변경 | 확인할 근거 |
| --- | --- |
| 설명·frontmatter | YAML 파싱, 이름·길이·지원 필드·사용 시점 |
| 경로·참고 파일·생성 원본 | 상대 경로·링크·코드 fence·생성 결과 일치 |
| 실행 도구 | 실제 입출력·실패 조건의 집중 회귀 검사 |
| 호출 조건·권한·흐름 | 대표 작업의 실행·결과 |
| 언어·구성 | 의미·조건·불확실성·보호 문자열·요청 형식·편집 범위 |

## 결과

수정된 계약과 원본 경로, 형식·설치·명시 적용·자동 호출·결과 품질별 확인 상태, 실제 실행 근거와 남은 불확실성을 보고한다.

## 예시

입력: “번역 키의 누락을 검토하는 스킬을 만들어 줘.”

본문 예시:

```markdown
---
name: reviewing-translation-keys
description: 번역 리소스 변경에서 기준 언어와 대상 언어의 키 누락을 검토할 때 사용한다.
---
기준 언어와 대상 언어의 키를 대조하고 누락의 사용자 영향을 확인한다.

## 절차
1. 기준 언어와 대상 파일을 확인하고 기존 키 검사기를 실행한다.
2. 누락된 키의 호출 화면과 fallback 동작을 읽는다.

## 결과
파일·누락 키·화면 영향과 검사 상태를 보고한다.

## 예시
입력: ko.json에는 저장 버튼 키가 있고 en.json에는 없다.
결과: en.json의 저장 버튼 키 누락과 해당 버튼의 fallback 표시를 보고한다.

## 참고 자료
저장소의 번역 리소스 계약을 읽는다.
```

## 경계

- Git·게시 작업은 각각의 사용자 승인 범위에서 진행한다.
